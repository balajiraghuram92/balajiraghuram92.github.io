Lesson 20 · Hands-on code explainer · Embeddings, similarity and reranking

Search by meaning: embeddings, similarity and reranking

Turn words and sentences into lists of numbers, find the closest matches to a question with cosine similarity, then let a second, more careful model put the best answers first. Three small starter files, every block explained, all running free on your laptop.

1

What you'll be able to do after this module

You will build a tiny search engine that finds text by meaning, not by matching words. Then you will make it more accurate with a second step called reranking. This is Module 1 of the hands-on workshop RAG and Tool Calling.

💡 Three files, three ideas

  1. 1_word_embeddings.ipynb: a word becomes a list of numbers (an embedding). You do "word maths" such as king − man + woman ≈ queen, and you write the cosine similarity formula yourself.
  2. 2_similarity_search_app.py: a small web app. Paste documents, type a question, get the top K closest documents. This is the "R" (retrieval) in RAG.
  3. 3_reranking_app.py: the same search, plus a second, slower model that re-reads the top K and puts them in a better order. This is how production RAG systems do it.

Why this matters in a real RAG system

RAG (retrieval-augmented generation) means: before an LLM answers, you look up the most useful pieces of your own documents and paste them into its prompt. If the lookup brings back the wrong pieces, the LLM answers from the wrong facts. So the lookup is where most RAG quality is won or lost.

  • Keyword search fails on meaning. The sample query in file 2 is fruit and nutrition. The line Bananas are a great source of potassium. shares no word with it, so a plain keyword search would never find it. An embedding search can, because "banana" and "fruit", "potassium" and "nutrition" live close together in meaning.
  • Fast search is rough. Comparing one query vector with millions of stored vectors is quick, but it can rank a vague line above a really useful one.
  • Reranking fixes the order. A slower, more careful model re-scores only the few best candidates. You get most of the accuracy for a small part of the cost.

🔧 Analogy: hiring

A recruiter skims 1,000 CVs in an hour and keeps the 10 that look right (fast, rough: the retrieval step). Then the hiring manager interviews those 10 properly, one by one (slow, careful: the rerank step). Nobody interviews all 1,000. Nobody hires straight from the skim.

⚠️ These are starter files

Each file has numbered # ----- TODO ----- blocks with hints, and placeholder lines such as return 0.0 # replace with the formula. Until you fill them in, the apps open but return empty or zero results. This page explains every TODO and, inside a closed "One possible answer" box, shows one way to solve it. Try first, then peek.

The big picture: retrieve, then rerank

Every RAG system you will meet does some version of this flow.

Step 1 runs on every document; step 2 runs only on the K documents step 1 kept. That is the whole trick.

1.1

Load a ready-made embedding model

GloVe: 400,000 words, each one a list of 50 numbers.

A computer cannot read the word king; it can only do maths on numbers. An embedding is a list of numbers that stands for a piece of text. The key property: texts with similar meaning get similar lists.

1_word_embeddings.ipynb · code cell 1 of 7

print("Words in vocabulary:", len(model.key_to_index))
Saved output in the notebook file (cell 1)
Words in vocabulary: 400000
  • gensim.downloader fetches pre-trained vectors by name. Pre-trained means someone else already did the expensive learning; you just load the result.
  • GloVe learned its numbers by counting which words appear near which other words in Wikipedia and news text. Words used in similar company ("king", "queen", "prince") end up with similar numbers.
  • model.key_to_index is the vocabulary: a dictionary from word to row number. Its length is the number of words the model knows.

🔧 Analogy: a map of meaning

Think of every word as a pin on a huge map. Similar words are pinned close together: fruits in one area, sports in another, royalty in another. The 50 numbers are the pin's coordinates. A paper map has 2 coordinates; this map has 50, which leaves room for many kinds of "closeness" at once.

🌍 Where you see this

Word vectors like GloVe and word2vec were the first big step in modern NLP. Today's sentence-embedding models (file 2) and the embeddings inside every LLM grew out of the same idea: meaning as position in a space of numbers.

⚠️ Analogies are not magic

Word maths works well on famous examples and badly on many others. The vectors also copy the biases of the text they learned from (for example, job words leaning male or female). Treat the demo as intuition, not as a reasoning engine.

1.4

Cosine similarity by hand, and why we normalise

TODO 4: the one formula every RAG system uses.

A 2-D sketch to build intuition, not real GloVe numbers. Real vectors have 50 or 384 directions, but the idea is the same: only the angle between arrows counts.

Cosine similarity measures the angle between two vectors:

cosine(a, b) = (a · b) / (|a| × |b|)
  • a · b (the dot product): multiply the two lists number by number and add everything up. Big when both vectors are large in the same places. In numpy: np.dot(a, b).
  • |a| (the length or norm): how long the arrow is. In numpy: np.linalg.norm(a).
  • Dividing by both lengths is called normalising. It cancels out how long the arrows are, so only the direction is left. The result is between −1 and 1: close to 1 means very similar meaning, close to 0 means unrelated.

One possible answer (written for this page, not in the starter file)
def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

💡 Why not just use the dot product?

The raw dot product grows with the length of the vectors, and length often reflects things you don't care about (how common a word is, how long a sentence is). Two texts about the same topic should score high whether they are short or long. Normalising removes length, so the score is about meaning only.

Bonus: if every vector is normalised to length 1 ahead of time, cosine and dot product become the same number, and the dot product is cheaper. Many vector databases store normalised vectors for exactly this reason.

🔧 Analogy: compass directions

Two hikers walking north-east are heading the same way, even if one walked 2 km and the other 20 km. Cosine compares the compass heading, not the distance walked.

def retrieve_top_k(documents_text, query, k):

    # 1. One document per non-empty line

💡 What "top-K" means

K is just "how many results to keep". In RAG, those K chunks are what gets pasted into the LLM's prompt. Too small a K and you may miss the answer; too big and you fill the prompt with noise (and pay for more tokens).

🔧 Analogy: a library's "closest matches" shelf

The librarian measures how close every book is to your question, lines them up from closest to furthest, and hands you the first K. That's all a basic retriever does.

⚠️ It always returns K results, even bad ones

Similarity search ranks; it does not judge. Ask about "cricket" and you still get K results, even if only one is about cricket. Real systems often add a minimum score, or a reranker (file 3), to drop weak matches.

3.1

Two models: a bi-encoder and a cross-encoder

The fast one finds candidates; the careful one orders them.

In the file's own words (docstring, lines 7–10)

  Step 1  RETRIEVE (fast, rough)   -> bi-encoder: embed query and documents SEPARATELY,
                                      compare with cosine similarity, keep the top K.
  Step 2  RERANK   (slow, precise) -> cross-encoder: reads the query AND one document TOGETHER
                                      and gives a relevance score. Re-sort the K results.
3_reranking_app.py · lines 17–27
import gradio as gr

🔧 Analogy: photos vs a conversation

A bi-encoder is like comparing two passport photos taken separately: quick, and you can file the photos in advance. A cross-encoder is like sitting both people at the same table and watching how they interact: much more informative, but you have to do it fresh for every pair.

from sklearn.metrics.pairwise import cosine_similarity brings in scikit-learn's ready-made cosine, so you don't write it a third time. Unlike your version, it works on whole grids of vectors at once (see 3.3).

  • Lines 2–4 ("COVID-19 symptoms are bad", "… not nice", "… really bad") repeat the query words but tell you nothing. They look very similar to the query COVID-19 Symptoms, so a bi-encoder may score them highly.

💡 What to look for when you run it

Compare the two tables. The question is: do the informative lines (5 and 6) move up after reranking, and do the empty "symptoms are bad" lines move down? Run it and see for yourself. Then think about where the trap line ends up.

⚠️ Relevance is not truth

Both models score how well a passage matches a question, not whether it is true. A confident, on-topic, wrong passage can still rank well. In real RAG that is why the quality of your documents matters as much as the search.

Speed vs accuracy: why production uses two steps

Put the pieces together.

ApproachHow many model runs per searchResult
Bi-encoder only (file 2)1 (the query); document vectors were made earlierFast; order is rough
Cross-encoder on every documentOne per document: a million documents means a million runsAccurate, but far too slow for big collections
Retrieve, then rerank (file 3)1 for the query + K for the rerankNearly the accuracy of the cross-encoder, at a cost you control with K

💡 Choosing K

K is the dial between the two steps. A bigger K gives the reranker more chances to find the best passage (better recall, meaning fewer good passages missed), but makes step 2 slower. A common pattern is to retrieve a few dozen candidates and pass only the top handful of reranked results to the LLM.

Quick quiz

Answer in your head, then open each one.

1. Why can an embedding search find "Bananas are a great source of potassium." for the query "fruit and nutrition" when keyword search cannot?

Keyword search needs shared words, and there are none. Embeddings place texts by meaning, so banana/fruit and potassium/nutrition end up close together.

2. What does dividing by |a| × |b| do in the cosine formula?

It normalises: it removes the vectors' lengths, so only their direction (meaning) affects the score, and the result stays between −1 and 1.

3. Why does the notebook use most_similar(positive=..., negative=...) instead of searching with king − man + woman directly?

Searching with the raw vector often returns one of the input words, such as king itself. most_similar does the same maths and skips the input words.

4. What is the main difference between a bi-encoder and a cross-encoder?

A bi-encoder embeds the query and each document separately and compares vectors (fast, document vectors can be stored ahead of time). A cross-encoder reads the query and one document together and outputs a score (slower, more accurate).

5. Why not run the cross-encoder on every document?

It needs one model run per (query, document) pair, for every search. On a large collection that is far too slow, so it only reranks the top K.

6. In file 3, the best document was not in the Top-K table. Can rerank fix that?

No. on_rerank only sees the documents in the Top-K table. Reranking can reorder, not recover; raise K or improve retrieval.

7. Does anything in this module need an OpenAI key?

No. All three files run local, free models (GloVe, all-MiniLM-L6-v2 and ms-marco-MiniLM-L6-v2). The .env file is for later modules.

Glossary

Embedding
A list of numbers that stands for a word or text. Similar meanings get similar lists.
Vector
Another name for a list of numbers; think of it as an arrow in a space with many directions.
GloVe
A set of pre-trained word vectors (here 50 numbers per word, 400,000 words).
gensim
A Python library that, among other things, downloads and searches word vectors.
Dot product (a · b)
Multiply two vectors number by number and add up the results.
Norm |a|
The length of a vector.
Normalise
Divide by length so only direction matters.
Cosine similarity
How closely two vectors point the same way: near 1 similar, near 0 unrelated.
Sentence transformer
A model that turns a whole sentence into one embedding.
Bi-encoder
Embeds query and documents separately, then compares vectors. Fast.
Cross-encoder
Reads a query and one document together and outputs a relevance score. Slower, more accurate.
MS MARCO
A large dataset of real search queries and answer passages, used to train the cross-encoder.
Top-K
The K highest-scoring results.
Retrieval
Finding the documents most relevant to a query: the R in RAG.
Reranking
Re-scoring and re-sorting the retrieved candidates with a more careful model.
Recall
How many of the truly useful documents your search managed to find.
RAG
Retrieval-augmented generation: look up relevant text first, then let the LLM answer using it.
Gradio
A library that builds a small web app from Python functions.
DataFrame
A pandas table with named columns.
